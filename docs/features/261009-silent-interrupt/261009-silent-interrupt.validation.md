# silent-interrupt 用户验证

## 验证说明

- 验证对象：`onNewMessage=interrupt`（新消息打断正在生成的旧回合）时，旧回合是否**不再出现那条「已停止。」提示**；显式 `/stop` 是否仍保留反馈。
- 环境/前置条件：Telegram 渠道（你的主场景）；全局拟人化设置已是本机现状（`streaming=true`、`messageBreak=true`、`onNewMessage=interrupt`）。
- **需先让新构建生效**：已 `npm run build`；重启 dsh（`sv restart dsh`）后新行为才生效——重启线上实例前请确认。

## 验证项

| 验证步骤 | 预期结果 | 实际结果 | 状态 | 备注/证据 |
| --- | --- | --- | --- | --- |
| 1. 在 Telegram 私聊发一条会生成较久回复的消息，等它开始出字后紧接着再发一条新消息 | 旧回合**不再出现**「已停止。」气泡；只有新消息的回答到达 | | 待验证 | 本次要修的就是这一条 |
| 2. 同上，重点观察打断后的几秒内：旧回合那半截流式预览是否残留成「幽灵气泡」 | 旧预览很快消失或被新回合的预览取代，不会停留约 30 秒 | | 待验证 | 私聊走 30 秒 Rich Draft；改动后不再靠 finish 顺带清稿，需实机确认（检视 S3） |
| 3. 对一条长回复中途发送 `/stop` | 仍按旧行为反馈「已停止。」（显式停止保留提示） | | 待验证 | 确认没有把 /stop 一起改静默 |

## 已知边界（不算不通过）

- 若旧回合在被打断前已经产生了部分回答文本，这段**部分回答仍会作为正常回复送出**（与 `/stop` 一致，属既有语义）。
- 群聊/非私聊渠道的流式载体（占位消息）无法被删除，打断后可能留下已推送的部分内容——本次只保证不再新增「打断提示」。
