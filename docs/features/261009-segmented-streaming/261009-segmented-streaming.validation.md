# 分段流式（message_break × streaming）用户验证

## 验证说明

- 验证对象：`streaming=true` + `messageBreak=true` 同时开启时的新行为——每段各自流式输出，断点处定稿为一条真实消息；`streaming=false` 的分段直发行为不变。
- 环境/前置条件：
  1. 拟人化设置：**流式回复 = 开**、**分步消息 = 开**（过程进度提示开/关都可以）。
  2. `npm run build` 已完成，且 **dsh 已重启**（link 部署，lib/ 为构建产物，不重启不生效）。
  3. 客户端必须是 **Telegram 官方客户端**：Telegram X 渲染不了 Rich Message，草稿会显示为「不支持的消息」，无法判断流式是否生效（见 `docs/issues/260909-telegram-unsupported-message/`）。
  4. 需要一轮**模型会调用 `message_break` 的长回复**（例如让它「分几段讲一个长话题，段落之间换气」）。

## 验证项

| 验证步骤 | 预期结果 | 实际结果 | 状态 | 备注/证据 |
| --- | --- | --- | --- | --- |
| 私聊里让机器人给出一段会在段落间调用 `message_break` 的长回复 | 第 1 段在草稿里逐字增长 → 断点处草稿变成一条真实消息 → 第 2 段在新草稿里逐字增长 → 尾部同样逐字后定稿；最终得到多条顺序消息，没有重复段落 | | 待验证 | |
| 在群聊或 Topic 里重复上一步 | 每段各自成为一条群消息；段内仍逐字更新（编辑占位消息），不出现空消息 | | 待验证 | |
| 让它以断点收尾（例如「分两段说，说完就停」） | 不出现空消息、不出现把整段内容重复发一遍的收尾消息 | | 待验证 | |
| 把「流式回复」关掉后再跑一次（回归） | 分段各自整条发出，段间有拟人停顿，行为与改动前一致 | | 待验证 | |
