# message_break 非 IM 门控 — 用户实机验证

改动要重启 dsh 才生效（link 部署，dsh 直接加载 `lib/`）。重启后请确认：

## 1. 非 IM 会话不再被引导（本单主目标）

在 **Web GUI** 里开一个新会话，让它写一段较长的回答（例如「用 5 段讲讲 X」）。

- 期望：回复**不分段**，也不出现 `message_break` 工具调用记录；模型不会再输出「我先分段发给你」之类的话。
- 反例（若仍出现工具调用）：说明 gate 没生效，需要检查 dsh 是否真的加载了新 bundle。

## 2. IM 会话分段照旧

在 Telegram（或任一已接入渠道）里让它写一段长回答。

- 期望：和以前一样分成多条消息，中间有自然的停顿感。
- 这是本改动最容易误伤的地方（若某个 IM 回合拿不到投递消费者，分段会被拒），所以要重点看。

## 3. 观察点（可选）

如果某次 IM 回复出现工具错误提示、且提示里带「no IM delivery consumer」，请把那一轮的会话 id 和时间告诉我——说明该渠道的提问路径没有登记消费者，需要单独修。
